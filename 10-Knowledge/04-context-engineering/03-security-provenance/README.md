# 安全边界与来源追踪

> 状态：draft
> 目标：把“能否读取”“是否可信”“如何追溯”从相关性排序中分离出来。

## 三个不能混成一个分数的问题

1. **权限**：当前主体能否读取正文？这是读取前的硬门禁。
2. **信任**：内容能否提出建议，还是有权改变系统约束？外部内容默认只是数据。
3. **相关性**：在已获准读取的候选中，哪部分最值得占用本轮预算？这是后续软排序。

若先把正文送给嵌入、重排或摘要服务，再过滤权限，数据已经越过边界。“最终没放进 Prompt”不能撤销这次泄露。因此候选应先只有元数据引用，权限通过后才调用加载器。

## 最小元数据

```yaml
id: "trace:run-042"
tenant: "alpha"
kind: "tool_result"
trust: "runtime"
version: "runner:v3"
expires_at: "2026-09-12T10:20:00+08:00"
sensitive: false
fact_key: "tests.payment.status"
authority: 20
```

- `tenant`、访问标签和敏感度用于读前授权；
- `version` 与 `expires_at`用于防止旧状态冒充当前状态；
- `fact_key` 用于显式发现冲突，不应靠相似度静默择一；
- `authority` 只能在同类规则允许的范围内比较，不能让高相关性覆盖系统约束。

## 派生内容的来源记录

摘要、去重和结构化抽取都应生成变换记录：

```json
{
  "output_id": "summary:run-042",
  "source_ids": ["trace:run-042"],
  "method": "structured_extract:v2",
  "lossy": true
}
```

记录至少回答：输出从哪里来、用了什么方法、是否有损、能否回读原文。只保留摘要正文或只保留最终 Prompt，无法区分检索失败、转换失真和模型未使用证据。

## 冲突与覆盖

- 约束不能被较晚的普通观察覆盖；
- 同一事实键的不同值默认产生警告或中止；
- 工具失败状态不能通过摘要变成成功；
- 精确重复可以确定性合并，但要保留所有来源 ID；
- 语义近似不等于事实相同，不能自动去重。

## 日志与隐私

Trace 也可能泄露正文、密钥、PII 和工具参数。默认只记录必要元数据、哈希或可控引用；确需保存正文时，沿用源数据的访问控制、保留期限与删除机制。不要为了可观测性建立一个权限更宽的影子数据库。
